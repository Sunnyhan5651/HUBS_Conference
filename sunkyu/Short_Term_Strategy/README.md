## 3. 이해관계자별 단기 전략

### 3.1 기업 (수출입기업·무역상사)

#### 핵심 문제

수출입기업이 실제로 부담하는 비용 구조는 다음과 같다.

| 비용 항목 | 현행 구조 | 스테이블코인 적용 시 변화 가능 범위 |
|-----------|-----------|--------------------------------------|
| 해외 송금 수수료 | SWIFT: 건당 $20–$50 + 수취수수료 | 네트워크 수수료 $0.01–$1 수준으로 감소 가능 |
| 정산 소요 시간 | 2–5 영업일 (시간대·중개은행 경유) | 수 분~수 시간 (24/7) |
| 선예치 자금 | 코레스 계좌 유지·노스트로 잔고 선적치 필요 | 거래 시점에 토큰 취득 후 즉시 전송 가능 |
| 환전 비용 | 미드마켓 대비 0.5–2.0% 스프레드 | 코인 취득·상환 시 환전 비용 별도 발생 (중복 가능) |
| 대사(reconciliation) | 복수 중개은행 경유 시 인력·시간 비용 | 온체인 기록으로 자동화 가능성 |

**총비용 비교 원칙 (BIS 논의 반영):**  
비교는 "지급 승인 → 토큰 취득 → 전송 → 수취 확인 → 상환·환전 → 법정통화 사용 가능 → 회계 대사" 전 과정을 포함해야 한다. 전송 속도만 빨라지고 환전·상환 단계에서 비용이 발생하면 실질 절감이 발생하지 않을 수 있다.

의사결정 수식:

```
ΔC = (c_legacy − c_stable) · V

ΔC  : 비용 절감액
c_legacy : 건당 기존 총비용 (수수료 + 선예치 기회비용 + 대사 비용)
c_stable : 건당 스테이블코인 총비용 (취득 + 전송 + 상환·환전 + 시스템 연결)
V   : 연간 해당 거래 건수 또는 거래액
```

ΔC > 0인 구간이 확인될 때만 파일럿을 확대한다.

#### 단기 실행 순서

**Step 1 — 후보 거래 구간 식별 (0~3개월)**

다음 조건을 모두 충족하는 거래 구간을 우선 선정한다.

- 동일 거래처에 월 2회 이상 반복 지급
- 현재 SWIFT 또는 수취인 현지은행 경유로 T+2 이상 소요
- 수취인 측 법정통화 환전 경로가 확인됨
- 거래 통화가 달러 표시 (원화 코인은 수취인 수요 별도 확인 필요)

후보에서 제외할 구간:

- 신용장(L/C)·기한부 결제로 금융 기능이 결합된 거래 (금융 기능은 별도 해결 필요)
- 일회성 거래·미확인 수취인
- 기존 결제가 이미 T+1 이내이고 수수료도 낮은 구간

**Step 2 — 기존 비용 기록 (0~3개월, Step 1과 병행)**

파일럿 전에 현재 비용을 거래 단위로 기록한다.

```
측정 항목: 
  - 건당 수수료 합계 (송금은행 + 수취은행)
  - 코레스 계좌 선예치 잔고 × 조달금리 × 체류기간
  - 대사 인력·시간 비용 (월 환산)
  - 환전 스프레드 (매도율 − 미드마켓)
```

이 기록이 없으면 파일럿 후 절감 효과를 증명할 수 없다.

**Step 3 — 소규모 파일럿 설계 (3~6개월)**

국내 기본법 시행 전에는 현행 외환·지급결제 규정 내에서 허용되는 범위를 법무 검토로 확정한 후 진행한다.

| 파일럿 설계 요소 | 내용 |
|-----------------|------|
| 규모 | 전체 거래량의 5% 이하로 시작 (리스크 제한) |
| 파트너 | 발행사 또는 은행 컨소시엄 제휴 채널 활용 |
| 기간 | 3개월 이상 (계절성·이례 거래 제거 가능한 충분한 기간) |
| 성공 기준 | Step 2에서 측정한 ΔC > 0 확인, 수취인 반복 이용 지속 |

**Step 4 — 결과 평가 및 확대 판단 (6~12개월)**

판촉비·무료 수수료 없이도 거래처가 반복 사용하는지를 핵심 기준으로 삼는다.

### 3.2 은행

#### 핵심 리스크: 예금 이탈

```
ΔD ≈ −β · S

ΔD : 예금 감소액
S   : 스테이블코인 발행·유통 규모
β   : 예금-스테이블코인 대체 탄력성
```

β의 크기는 스테이블코인 준비자산이 은행 예금 형태로 재예치되는 비율에 따라 달라진다. 연준 연구에 따르면 준비자산 배분 방식에 따라 은행별 유입·유출이 달라지므로, 산업 전체 영향보다 **개별 은행의 역할 확보 여부**가 중요하다.

단기에 β를 낮추는 것보다 **준비자산 수탁·기업 정산 역할을 선점해 스테이블코인 생태계 내 수익 채널을 확보하는 것**이 더 유효한 전략이다.

#### 단기 실행 순서

**Step 1 — 내부 역할 선정 (0~3개월)**

직접 발행, 발행사 제휴, 준비자산 수탁, 기업 정산 서비스 네 가지 경로를 다음 기준으로 비교한다.

| 역할 | 수익원 | 필요 조건 | 단기 실행 가능성 |
|------|--------|-----------|-----------------|
| 직접 발행 | 준비자산 운용수익 (r·R − C 구조) | 인허가, 상환체계, 유통망 구축 | 기본법 시행 전 제한적 |
| 발행사 제휴 (유통 역할) | 유통 수수료 (Circle 구조 벤치마킹) | 제휴 계약, 고객망 | 현행 체계에서 검토 가능 |
| 준비자산 수탁·예치 | 예치 수수료, 자금 유치 | 신뢰·안전성 인증 | 높음 |
| 기업 정산·환전 서비스 | 정산·환전 수수료 | 기업 고객 수요 | 높음 |

단기에는 **준비자산 수탁 + 기업 정산 서비스**를 우선 추진하되, 발행 역할은 기본법 시행 후 인허가 완성 시점으로 미루는 것이 현실적이다.

**Step 2 — 기업 고객 수요 조사 (0~3개월, Step 1과 병행)**

기존 기업 고객(수출입기업·무역상사) 중 다음에 해당하는 수요를 파악한다.

- 해외 정산 비용 절감 수요 (어느 거래처, 어느 통화)
- 자금관리(treasury) 업무의 스테이블코인 연계 수요
- 현재 이용 중인 해외 정산 경로의 불편 사항

이 조사 결과는 은행이 참여할 컨소시엄 설계와 파일럿 우선순위에 직접 반영된다.

**Step 3 — 컨소시엄 참여 구조 결정 (3~6개월)**

참여 전에 다음 다섯 가지를 계약으로 명확히 한다.

1. 반복 거래 고객을 누가 확보하며, 고객은 무엇에 비용을 지불하는가
2. 신규 수익과 공동 운영비를 어떤 기준으로 배분하는가
3. 상환·장애·분쟁 손실을 누가 부담하는가
4. 유통량이 기대보다 작아도 은행 사업이 유지되는가
5. 다른 발행사나 결제수단으로 전환할 수 있는가

US 참조 사례:
- Visa: 기존 카드 고객 경험 유지 + 후방 정산만 USDC로 전환 (Cross River Bank·Lead Bank, 2025-12-16)
- FIS: Circle과 제휴해 은행 고객에게 스테이블코인 결제 기능 공급 (2025-07-28)

**Step 4 — 내부 예금 영향 측정 시스템 구축 (0~6개월)**

스테이블코인 유통량 확대 시 예금 이탈 규모를 추적할 내부 모니터링 체계를 갖춘다.

```
측정 지표:
  - 법인 예금 중 스테이블코인 정산 전환 비율
  - 준비자산 예치 유입 규모
  - 수수료 수익 변화 (정산·환전·수탁)
  - 전체 조달비 변화
```

예금 감소 절대값보다 **수수료 수익 증가가 조달비 증가를 상쇄하는지** 여부가 핵심 판단 기준이다.

### 3.3 발행사

#### 핵심 수익 구조

```
Π(r) = r · R − C

r  : 준비자산 운용금리
R  : 평균 유통 잔액 (준비자산 규모)
C  : 운영 비용 (인허가·감사·유동성·유통 파트너 배분 포함)

임계 금리: r* = C / R
  → r > r* 일 때만 흑자
  → 금리 하락 또는 R 감소 시 손익 역전 가능
```

Circle 2025 Form 10-K 기준: 준비자산 수익이 총수익의 96.0%를 차지하며, 유통 파트너 배분 비용이 손익의 핵심 변수임.

#### 단기 실행 순서

**Step 1 — 발행 가능 경로 확인 (0~3개월)**

국내 기본법 시행 전·후 시나리오별로 허용 경로를 법무 검토한다.

| 제도 시나리오 | 발행 경로 | 단기 준비 항목 |
|--------------|-----------|----------------|
| 은행 중심 발행 구조 | 컨소시엄 참여 (유통·IT 역할) | 파트너 은행과 역할·수익 배분 협의 |
| 비은행 발행 허용 | 독립 발행 또는 전문 발행사 제휴 | 인허가 요건·최소자본 50억 충족 계획 수립 |
| 발행 인허가 지연 | IT·대사·정산 서비스 역할 | 발행 없이도 수익이 발생하는 서비스 계약 확보 |

**Step 2 — r* 시뮬레이션 (0~3개월)**

소규모 시범 발행 전에 금리 시나리오별 손익 분기점을 계산한다.

```
예시 (최소자본금 50억 기준):

  가정: R = 500억 (최소 규모), C = 15억/년 (운영·감사·유통 배분)
  r* = 15억 / 500억 = 3.0%

  → 준비자산 운용금리가 3.0% 이상 유지되어야 흑자
  → 2024-2025년 한국 국채 금리 3.0–3.5% 구간 → 경계선
  → 금리 1%p 하락 시 Π = (2.0% - 3.0%) × 500억 = −50억/년
```

금리 하락 리스크는 두 가지 방법으로 관리한다.

| 헤지 수단 | 방법 | 비용 |
|-----------|------|------|
| 금리스왑 (IRS) | 고정금리 수취 계약으로 하방 고정 | 스왑 비용 (시장금리 - 고정금리 차이) |
| 캡(Cap) | 금리 하한 설정 옵션 구매 | 프리미엄 지불, 상방 이익 유지 |

단기에는 전체 R에 헤지를 걸지 않고 **핵심 잔액(core R)에만 IRS 적용, 변동 잔액은 단기물로 운용**하는 혼합 구조가 현실적이다.

**Step 3 — 상환 체계 구축 (3~6개월)**

발행량보다 상환 가능성이 더 중요한 리스크다. 단기 집중 상환에 대비해 다음을 준비한다.

- 유동성 준비 비율: 일별 예상 상환액의 최소 120% 유지
- 상환 처리 시간: 영업일 기준 T+1 이내
- 극단 시나리오: 24시간 내 30% 상환 요청 시 대응 계획

## 4. 실행 우선순위 및 타임라인

```
0–3개월  |  3–6개월  |  6–12개월
─────────┼──────────┼──────────────
[기업]   후보 구간 선정 + 비용 측정 → 소규모 파일럿 → 결과 평가
         ▲ ΔC 측정이 없으면 파일럿 효과 증명 불가

[은행]   역할 선정 + 고객 수요 조사 → 컨소시엄 계약 구조 → 준비자산 수탁 실행
         ▲ 역할 선정이 늦어지면 컨소시엄 내 위치 약화

[발행사] r* 시뮬레이션 + 경로 확인 → 금리 헤지 구조 설계 → (법 시행 후) 시범 발행
         ▲ 금리 하락 시나리오 미대비 시 발행 즉시 손실 구조 진입 가능
```

**우선순위 판단 기준:**  
세 이해관계자 전략이 독립적이지 않다. 은행의 기업 고객 수요 조사 결과가 기업 파일럿의 파트너 선택을 결정하고, 컨소시엄 역할 분담이 발행사의 유통 경로를 결정한다. 따라서 **은행의 역할 선정과 기업의 수요 파악이 가장 먼저 진행되어야 한다.**

## 5. 리스크와 전제조건

| 리스크 | 발생 조건 | 단기 대응 |
|--------|-----------|-----------|
| 국내 기본법 시행 지연 | 입법 협의 결렬 또는 총선 일정 충돌 | IT·대사·정산 서비스 역할로 수익 창출 가능 → 발행 의존 전략 분리 필요 |
| 은행 중심 독과점 구조 확정 | 기본법이 은행만 발행 허용 | 비은행은 유통·IT 역할 선점; 은행은 발행 선점 가속 |
| 준비자산 운용금리 급락 | 한국은행 금리 인하 | r* 시뮬레이션 기반 IRS 사전 체결 |
| 파일럿 후 수취인 미수용 | 거래처 시스템·규정 미비 | 파일럿 전 수취인 확약서 + 현지 법무 검토 선행 |
| SWIFT 망 병행 운영 비용 | 파일럿 기간 이중 시스템 운영 | 파일럿 구간을 전체의 5% 이하로 제한, 대체 경로 상시 유지 |

## 6. 단계 전환 판단 기준

다음 조건이 충족되면 중기 전략으로 전환한다.

| 이해관계자 | 중기 진입 기준 |
|------------|--------------|
| 기업 | 판촉비 없이 파일럿 거래처의 반복 사용이 3개월 이상 지속 + ΔC > 0 확인 |
| 은행 | 컨소시엄 계약 체결 + 준비자산 수탁 수수료 수익이 예금 이탈 손실을 상회 |
| 발행사 | 국내 기본법 시행 인가 취득 + r > r* 조건 충족하는 운용 구조 확보 |

반대로 보류·수정하는 조건:

- 전송 속도만 빨라지고 총비용·자금 절감이 확인되지 않음
- 판촉비를 제거하면 거래처 이탈
- 유통량 확대 시 운영비가 수익보다 더 빠르게 증가
