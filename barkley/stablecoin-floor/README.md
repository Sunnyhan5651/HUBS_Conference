# 스테이블코인 발행사의 금리 플로어 운용 최적화

가상자산 공모전 발제안 「디지털 자산의 제도화와 국내 기업의 대응 전략」의 금융공학 파트.

## 연구 질문

달러 스테이블코인 발행사는 금리 플로어를 어떻게 운용해야, **3년 누적 손실확률을 5% 이하**로 유지하면서 **헤지 비용(프리미엄)을 최소화**할 수 있는가?

$$\min_{K,\; h,\; T} \text{프리미엄}$$

$$\text{s.t.} \quad P(\pi_{3y} < 0) \leq 5\%$$

## 핵심 기호

| 기호 | 의미 |
|---|---|
| $r$ | 시장금리 (기준: SOFR) |
| $R$ | 준비금 규모 = 스테이블코인 발행량 |
| $C$ | 연간 고정비 |
| $s$ | 유통파트너 배분율 (Coinbase 등에 주는 준비금 수익 비중) |
| $\pi$ | 이익 $= (1-s)\cdot r\cdot R - C$ |
| $r^*$ | 손익분기 금리 $= C/R$ (배분율 반영 시 $C\,/\,((1-s)\cdot R)$) |
| $K$ | 플로어 행사가 |
| $N,\ h$ | 플로어 명목금액, 헤지 비율 $h = N/R$ |
| $T$ | 플로어 만기 (1년 롤링 vs 3년 등) |

## 전체 단계

1. **데이터 수집** — 금리·USDC·통제변수 완료, Circle 재무제표 남음
2. 금리 모형 (Hull-White 또는 Vasicek 파라미터 추정) — `03_rate_model.ipynb`에서 Vasicek 추정·검증·시험 시뮬레이션
3. 발행량 모형 (USDC 발행량 추세 + 금리와의 관계) — 회귀(`02_supply_regression.ipynb`)와 설계 완료, 시뮬레이션 코드는 아직
4. 플로어 가격 산출 (블랙 / 바슐리에)
5. 전략 후보 정의 (무헤지, K·h·T 조합, 칼라, 리시버 스왑)
6. 몬테카를로 시뮬레이션 (3년 누적 이익 분포)
7. 평가 (손실확률, 비용, 기대이익, 최악 5% 평균)
8. 효율적 투자선 + 5% 기준으로 최적 정책 선택
9. 규모 분석: R을 바꿔가며 플로어가 효율적이 되는 임계 규모 도출
10. 한계 점검 (모형 위험, 유동성, 거래상대방, 베이시스 위험)

## 1단계에서 모을 데이터

| 데이터 | 용도 | 출처 |
|---|---|---|
| SOFR 일별 (2018-04~) | 기준금리, 플로어 정산 기준 | FRED `SOFR` |
| 연방기금 실효금리 일별 (장기) | SOFR 이력이 짧아 금리 모형 캘리브레이션 보완 | FRED `DFF` |
| 3개월 국채 수익률 | 실제 준비금 수익률 대용, 베이시스 확인 | FRED `DTB3` |
| 미국채 수익률곡선 (1M~10Y) | 선도금리, 금리 기간구조 | FRED `DGS1MO`, `DGS3MO`, `DGS6MO`, `DGS1`, `DGS2`, `DGS5`, `DGS10` |
| USDC 유통량 일별 | 발행량 R의 이력, 금리와의 관계 | DefiLlama stablecoins API |
| Circle 재무제표 (분기) | 고정비 C, 배분율 s, 준비금 수익률 추정 | SEC EDGAR XBRL API (Circle CIK 1876042) |

- FRED는 API 키 없이 `https://fred.stlouisfed.org/graph/fredgraph.csv?id=<시리즈ID>` 로 CSV를 받을 수 있다.
- SEC EDGAR 요청에는 `User-Agent` 헤더(이름 + 이메일)가 필요하다.
- DataGuide(FnGuide)는 한국 데이터에 강하다. 원화 확장(KOFR, CD91, 국고채) 및 미국 금리 교차검증에 사용한다.

### 데이터 기간 기준

- 금리 데이터는 2000년~현재로 넉넉히 받는다
- 금리 모형 추정: 메인 2000년~, 민감도 분석 2008년~
- 금리 변동성: 최근 2~3년
- USDC 발행량 분석: 2020년~ (2018~19년은 규모가 작아 제외)
- Circle 재무제표: 2022년~ (현재 C와 s 추정용)
- 시뮬레이션 시작점: 가장 최근 데이터 날짜에서 3년 앞으로

## 3단계 발행량 모형 설계

시뮬레이션에서 준비금 $R$ (USDC 유통량)을 월 단위로 만드는 규칙. 근거는 `02_supply_regression.ipynb` (2020-05~2026-09 월간 회귀).

### 구조

$$\Delta \log(\text{USDC 제외 시장})_t = g + b_1 \cdot \Delta y_{2Y,\,t}$$

$$R_t = R_{t-1} \cdot \exp\!\bigl(\Delta \log(\text{USDC 제외 시장})_t\bigr) \cdot (1 + J_t)$$

- 점유율은 고정 → 점프가 없는 달에는 $R$의 성장률 = USDC 제외 시장의 성장률
- $J_t$: 발행사 고유 충격 (아래 3번). 충격이 없는 달은 0
- 비트코인 항($b_2$)과 시장 충격 더미($b_3$)는 시뮬레이션에 넣지 않음 (비트코인 경로를 따로 만들지 않기 때문)
- 미정: 매달 오차항(잔차 변동성)을 넣을지. 참고로 최근 24개월 월간 성장률의 표준편차는 0.029

### b1 시나리오 (02 노트북 결과)

| 시나리오 | $b_1$ | 근거 |
|---|---|---|
| 보수 | $0$ | 메인 결론 기준: 95% 신뢰구간이 0을 포함(상한 +0.004 ≈ 0) |
| 기본 | $-0.039$ | 메인 회귀 추정값 (HAC 표준오차 0.022, p=0.076) |
| 낙관 | $-0.083$ | 95% 하한, 자연 헤지가 가장 강한 경우 |

- 근거: 9개 설정 모두 $b_1$이 음수다. p값은 메인·전체 시장·기준금리 설정에서 0.06~0.10으로 경계 수준이다. 2022년 이후만 쓰면 $-0.012$로 약해진다.
- **최적 정책은 $b_1 = 0$ (보수) 시나리오로 결정한다.** 손실확률 기준에서는 자연 헤지를 기대하지 않는 $b_1 = 0$이 가장 보수적이기 때문이다. 기본·낙관은 민감도 분석으로 쓴다.

- 상수 $a$ (월 0.045)는 쓰지 않는다. 2020~21년 급성장기 때문에 커진 값이고, 2023년 이후 잔차가 대부분 음수(과대 예측)다.

### 1. 2년물 변화 계산

- 금리 모형(Vasicek/Hull-White)의 채권가격 공식으로 단기금리 $r$에서 2년물 금리를 계산한다.

$$y_{2Y} = \frac{-\ln A(2) + B(2)\cdot r}{2}, \qquad B(\tau) = \frac{1 - e^{-a\tau}}{a} \quad (a:\text{ 평균회귀 속도})$$

$$\Delta y_{2Y} = \frac{B(2)}{2} \cdot \Delta r$$

- 검증: 모형의 $B(2)/2$와, 실제 데이터에서 $\Delta$2년물을 $\Delta$SOFR로 회귀한 기울기를 비교한다.
- 한계: 1요인 모형이라 시장의 "기대 선행" 효과는 반영하지 못한다. 실제로는 2년물이 기준금리보다 먼저 움직인다(월간 변화 상관 약 0.2, 의미 있게 움직인 달 비율은 기준금리 35%, 2년물 68%).

### 2. 성장률 g (상수 a 대신)

| 시나리오 | 월간 로그 성장률 $g$ | 연 환산 |
|---|---|---|
| 기본 | $0.0219$ | $+30.1\%$ |
| 중간 | $0.0110$ (기본의 절반) | $+14.1\%$ |
| 보수적 | $0$ | $0\%$ |

- 기본값 근거: USDC 제외 시장의 최근 24개월(2024-10 ~ 2026-09) 평균 월간 로그 성장률. 시장은 137.1bn → 232.1bn
- 이 24개월은 인하기와 GENIUS법이 겹친 성장기라, 기본값 자체가 낙관적일 수 있다

### 3. 발행사 고유 충격 (점프)

- 점유율은 기본적으로 고정하되, 발행사 고유 충격을 점프로 추가한다. 충격이 나면 $R \leftarrow R \times (1 + J)$
- 기본값: 연 발생확률 약 $1/3$ (월 확률 $= 1 - e^{-1/36} \approx 2.7\%$), 충격 크기 $J = -30\%$
- 민감도: 점프 없음 / 기본 / 빈도 2배 (연 약 $2/3$)
- 근거 데이터 (`usdc_rates.parquet`, 점유율 = USDC ÷ 전체 시장)

| 사례 | 구간 | USDC 점유율 | USDC 유통량 | USDC 제외 시장 |
|---|---|---|---|---|
| 바이낸스 자동전환 | 2022-09-28 → 10-31 | 32.2% → 29.5% (−8.4%) | −11.3% | +0.7% |
| SVB 디페깅 | 2023-03-09 → 03-31 | 32.1% → 24.7% (−22.9%) | −24.5% | +8.5% |
| SVB 디페깅 | 2023-03-09 → 06-30 | 32.1% → 21.7% (−32.5%) | −35.8% | +9.8% |
| SVB 디페깅 | 2023-03-09 → 12-31 | 32.1% → 18.4% (−42.5%) | −44.4% | +16.3% |

- 빈도: 2020-05 ~ 2026-09(6.4년) 동안 2건 → 연 0.31건 ≈ $1/3$
- 크기 $-30\%$는 SVB 약 4개월치($-32.5\%$)에 해당하는 **심한 쪽** 값이다. 바이낸스는 $-8\%$ 정도였고, FTX 직후 USDC로 자금이 옮겨 오면서 12월에 점유율이 거의 회복됐다. 두 사례 평균은 약 $-20\%$
- 충격이 나도 USDC 제외 시장은 오히려 늘었다 → 충격은 시장이 아니라 $R$에만 적용
- SVB 이후 점유율은 회복되지 않았다(2023-12-13 최저 18.1%) → 점프는 되돌리지 않는 영구 충격으로 둔다

## 작업 방식 (중요)

- 사용자는 경제·금융 복수전공 3학년, 파생상품 기초는 탄탄하지만 **수학과 코딩은 아직 익숙하지 않다.** 이 프로젝트로 데이터 수집·분석을 배우고 싶어한다.
- **주피터 노트북으로 단계별로** 진행한다. 한 셀에 한 가지 일만 하고, 셀마다 위에 마크다운으로 "이 셀이 하는 일"을 쉬운 한국어로 적는다.
- 코드 주석과 설명은 **최대한 쉬운 한국어**로. 전문용어는 처음 나올 때 한 줄로 풀어서 설명한다.
- 수식은 결과를 해석하는 데 필요한 만큼만 쓰고, 항상 직관적인 의미를 함께 적는다.
- 원본 데이터는 `data/raw/`에 받은 그대로 저장하고, 가공은 별도 단계에서 한다.
- 데이터를 받으면 기간, 결측치, 이상값을 먼저 확인하고 간단한 그래프로 보여준다.
- 그래프 제목과 축 이름은 한국어로 (한글 폰트 설정 포함).
